常见问题 出问题时看

常见问题与排查顺序

遇到问题时按这个顺序走：先确认日志目录，再读最新快照的堆栈第一行，最后对照下面的现象处理。

先看日志，不要猜

  • 主程序日志：/storage/emulated/0/LuaXPlus/logs
  • 成品日志：/storage/emulated/0/LuaXPlus/APP_Logs/包名
  • 按修改时间排序，最新的 luaerror_* 或 crash_* 就是现场。
快照文件名带毫秒，每次报错都是独立文件，不会互相覆盖。堆栈里的第一条通常直接指出脚本与行号。

module 'import' not found

脚本第一行就 require "import" 时报找不到模块，说明基础模块没有铺设到运行时目录。

  1. 确认设备已授权存储权限；未授权时铺设可能中断。
  2. 到私有目录 files/lua 看是否存在 import.lua。
  3. 清理应用数据后重装，让启动铺设重新执行一次。
  4. 成品包出现这个问题，通常是打包时没带上运行时模块，重新打包即可。

界面报「不是字段」或方法调用无效

典型提示如 xxx@Listener is not a field、Invalid method call，多半是脚本里用了不存在的属性或方法。

  • Java 控件只有 setter 方法，没有同名属性字段；用 setOnClickListener 而不是字段赋值。
  • 回调要写成表：View.OnClickListener{ onClick = function(v) ... end }。
  • 接口版本差异会导致方法签名不同，报错时按堆栈给出的类名核对。

启动就闪退

  1. 找最新的 crash_*.log，看异常类型与第一行「由谁抛出」。
  2. 如果是脚本层错误，会先有 luaerror_*.log，两者按时间对照看。
  3. 覆盖安装旧版本仍闪退时，先清理应用数据再试，排除残留脚本干扰。
  4. 把快照文件保留下来，它记录了版本、线程、机型与完整堆栈。

安装提示与系统不兼容

这是安装包归档或签名不满足系统要求，不是代码问题。当前版本已在打包环节处理：资源索引表不压缩且四字节对齐、签名补齐 v1/v2/v3。

  • 确认用的是最新主程序打的包，旧包不会自动变好。
  • 同包名旧版本先卸载，避免签名冲突被误判成兼容性问题。

权限开关是灰的

说明安装包清单里没有声明对应权限。当前版本打包会继承完整权限清单；如果仍为灰色，检查是不是用了旧版本打的包。

Java 编译提示未安装编译器

ECJ 与 D8 已从主程序安装包移出，改为按需下载的编译器插件。第一次预览或打包 Java 工程前需要先安装。

  1. 打开首页侧边栏「插件市场」，在「Java 编译器」卡片点「下载并安装」。
  2. 插件包约 29 MB，从 GitHub 下载后会校验 SHA-256；网络中断时重试即可，不会影响已有工程。
  3. 安装完成后回到 Java 工程重新预览；如果仍提示未安装，检查应用内部存储的 files/compiler-plugin 是否存在 compiler.dex 与 android.jar，或重新下载安装。

改了脚本但运行结果没变

  • 主程序在版本变化或重装后才重新铺设运行时脚本，工程脚本本身每次都重新读取。
  • 成品包是打包时的快照，改脚本必须重新打包。
  • 确认改的是当前工程目录下的文件，而不是外部目录里的另一份副本。

日志文件一直不更新

早期版本只有入口脚本错误会写快照。当前版本已覆盖：

场景落盘位置
脚本运行报错luaerror_*.log
运行时错误页错误页内容整段截取为快照
未捕获异常crash_*.log
警告warn_*.log 与当天日志

成品打开白屏或直接退出

  1. 先看 APP_Logs/包名 是否生成日志；没有日志说明启动阶段就出问题。
  2. 有 luaerror 时按堆栈定位脚本；有 crash 时看是否为 Java 层异常。
  3. 确认成品已获得存储权限，否则部分依赖外部目录的脚本会失败。

怎么彻底重置

  • 系统设置里清除应用数据：会清空私有目录脚本，下次启动重新铺设。
  • 删除 LuaXPlus/logs 只清主程序日志；成品日志按 LuaXPlus/APP_Logs/包名 单独清理，不影响工程。
  • 成品包各自独立，卸载成品只影响它自己的目录。
