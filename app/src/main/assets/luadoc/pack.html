打包与权限 发版前看

打包、签名与权限

打包会把当前工程组装成独立安装包，带上运行时模块、完整权限清单与日志系统。下面按顺序说明每一步做了什么、可能卡在哪。

打包做了什么

  1. 以主程序安装包为模板，替换包名、应用名、版本号与图标等清单信息。
  2. 把工程脚本编译进安装包，同时保留运行时基础模块与日志脚本。
  3. 重排归档结构，资源索引表改为不压缩并按四字节对齐，满足系统解析要求。
  4. 在设备上完成 v1 + v2 + v3 三段签名，然后自动拉起安装界面。
成品包与主程序共用同一套 Java 运行时，所以启动页、日志、崩溃监控、权限申请都不需要工程自己实现。
工程包含 .java 源码时，打包前会先在手机内编译 Java。ECJ 与 D8 不随主程序内置，请先在首页侧边栏「插件市场」安装「Java 编译器」；未安装时打包会停在 Java 编译步骤并给出提示。

成品包里带了什么

内容说明
工程脚本工程目录下的 Lua 文件，编译后写入安装包
运行时模块import、loadlayout、permissions、日志模块等
完整权限清单继承模板的全部权限，不再按工程声明裁剪
日志与监控启动即初始化，错误、警告、崩溃各自留快照

权限

权限分两层：清单声明与运行时授权。清单已由打包自动注入，你只需要在用到时申请：

import "permissions"
permissions.ensure("storage")   -- 打开所有文件访问授权页
permissions.ensure("camera", "microphone")
  • 存储权限在成品首次启动时也会自动申请一次。
  • 系统级授权（所有文件访问）必须在设置页手动打开，脚本无法代劳。
  • 拒绝授权不会导致崩溃，只会让相关功能不可用，日志会记录一条警告。

成品日志在哪

每个成品独立一个目录，包名即目录名：

/storage/emulated/0/LuaXPlus/APP_Logs/你的包名
    app_日期.log                  当天运行日志
    warn_日期_时分秒_毫秒_进程.log   警告快照
    luaerror_日期_时分秒_毫秒.log    脚本错误快照
    crash_ledger_日期_时分秒_毫秒_来源.log   崩溃账本
    native_crash_日期_进程_线程.log      原生崩溃现场

未获得存储授权时，日志先写在成品自己的私有目录，授权后 30 秒内自动切换。

安装被拒的常见原因

提示原因与处理
与当前系统有兼容性问题归档结构或签名不满足系统要求，重新打包即可；本版本已内置处理
签名冲突设备上已有同包名、不同签名的版本，先卸载旧包
解析包错误安装包传输中被截断，重新拷贝或重新打包
应用未安装空间不足、包名与已有应用冲突，或系统拦截了来源

导出前的检查项

  • 包名不与设备上已有应用冲突，版本号按需递增。
  • 工程内 main.lua 能在主程序里正常运行，没有报错。
  • 需要的权限已在脚本里申请，或首次启动时自动申请。
  • 打包完成后先在本机装一次，确认能进入界面再看日志目录是否生成。
打包成品使用的是内置测试密钥，仅适合本机测试与分发试用。对外发布的正式应用应使用自己的发布密钥签名的安装包，避免身份混用。
